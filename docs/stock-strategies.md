# 股票策略模拟

入口 `/strategies?market=CN|US`；详情 `/strategies/:strategyKey?market=CN|US`。
顶栏位于研究之后。模拟是全局共享研究结果，与用户真实持仓、现金和 Trade Engine 完全独立。

## 收益与成交口径

- 全模块首次运行时保存统一启动日期；各市场从该日及以后的首个交易日空仓开始。只以历史日线预热指标，不导入 discovery 历史利润。
- 每个 `strategy_key + version + market` 独立100万本币；A股人民币，美股美元。允许碎股，不计手续费、滑点和融资。
- T日收盘生成候选/退出计划；T+1开盘依序先卖后买，盘后用T+1闭合日线结算。无额外开盘或盘中任务。
- 开盘成交选择不查看执行日收盘、高低价或当日成交量。买入仅按事先冻结的候选；金额为 `min(现金, 当日开盘账户净值 / 仓数)`，已有股数不强制再平衡。
- 同证券每日最多一笔实际模拟成交，无同日卖出再买回。无有效开盘时不成交，未成交退出持续保留；买入候选只属于指定执行日。
- A股股票复用 `market_review/price_limits.py` 的板块/ST比例，以复权昨收和开盘涨跌幅作不可成交代理。ETF不猜测涨跌幅类别。这不是实盘可成交性认证。
- 没有有效收盘的持仓沿用最后估值，并保存/展示缺失证券和估值日期，不能把估算净值当成完整行情。
- 复权刷新时，比较当前DB中旧估值日的收盘与已存估值，按比例同步换算数量、成本、持仓峰值和ATR线，保持原有货币价值不变；待买候选的ATR也按信号日价格桥接。历史已保存快照不被改写。该桥接不是拆分、分拆、现金分红财富账本的完整重建。
- 单日收益为相邻结算净值比值减一，累计收益相对初始资金；CAGR采用实际日历时间/365.25，前20个结算日不展示。最大回撤为包含初始资金的历史净值峰值回撤（负值），与可重置的账户风控峰值独立。
- 图表基准为同起点沪深300ETF/SPY收盘持有收益，采用相同复权桥接。历史日线修订不重新计算已保存模拟收益。

### 需要保留的规则区别

- MA20/50：收盘>MA20>MA50、收盘>MA200且126日收益>0；按MA20/MA50−1降序，跌破MA20退出。股票和ETF共同排名；延续10/21研究对CTVA的排除。
- 动量60：60日收益>0及同样的长期过滤，按60日收益降序；仅月末最后交易日产生新买候选。跌破MA50/ATR每天检查，月末跌出前2也退出。
- 回归126：对数收盘OLS斜率年化乘R²，要求分数>0、收盘>MA100、126日窗口绝对单日涨跌幅<20%；有空位每日补仓，仅排名退出在月末检查前5。ETF非OFF可入，ETF/Trend60连续两日OFF清仓。
- CN混合：股票Trend60≥60/RS60≥50，ETF及Trend20市场均ON才新买；股票跌破此前20日低点或市场分数<60或ETF非ON退出。ETF为ForceIndex2回撤，EMA50高于五日前，且有长期趋势及Trend40/RS40过滤。股票优先填5仓，ETF使用剩余槽位。
- 突破变体：先取原股票前40候选，再要求收盘突破昨高，不从列表外递补；ETF分支不变。
- 广度：合格股票站上MA50比例≥40%才新买，连续两日<25%全账户退出；分母要求MA200和流动性。
- ATR14用连续14值SMA种子后Wilder递推，遇缺失重置；EMA亦使用连续SMA种子后递推。跟踪峰值取最高收盘，当前收盘先检查此前止损线，再更新峰值/线，次开盘执行。
- 10/21账户DD为严格超过，暂停结束且已空仓时重设本轮峰值；10/20为达到阈值，首笔成功重进时重设。暂停按交易日开盘计数，不按自然日；不能合并成一套含混规则。

## 数据适配与就绪

- 全部策略日常只读PostgreSQL，计算链不实例化远程行情Provider，不运行参数搜索，不调用LLM。
- 基准`510300.SH`/`SPY.US`由核心指数ETF固定清单纳入日线同步；迁移只补参考数据，
  日线需由维护任务同步后才就绪，见[核心指数ETF同步](core-index-etf-sync.md)。
- 各市场首次初始化时冻结股票、ETF、广度池及名称/类型，保存范围哈希。US股票为`us_trend`（标普500/中盘400/纳指100），CN为`cn_trend`（300/500/1000/2000）；ETF为各自index_etf池。
- US广度只用`us_sp500`成分，CN用已同步`cn_trend`；这里是成分股各自MA50广度，不是SPY自身MA20开关。原研究已用MA50，保留该周期。
- 股票/ETF当日有效收盘覆盖各至少98%，股票不足200交易日等条件不进入候选。此阈值不把真实缺失日补零或压缩掉。
- 混合/回归依赖目标日期正式ETF市场状态及相应Trend20/60市场状态，混合股票评分复用当日正式Trend60。缺失或不完整则等待，禁止回退旧日。
- ETF的Trend40/RS40使用研究公式在本轮冻结股票+ETF横截面共享计算；不为每个ETF另跑远程Trend服务。该横截面适配、固定范围和现行正式评分版本与原研究输入可能有差异，详情明确展示，不能直接沿用历史CAGR。
- 每个市场/日期只加载一次270个交易日以内的指标窗口（EMA/ATR在窗口内重新种子化，与全历史递推可能存在边界差异），数据库按证券流式读取标量列，避免构造百万条ORM对象；所有策略共享特征。窗口外估值锚点另按精确日期批量读取；仍缺失时等待，禁止猜测复权比例。

## 调度、恢复和失败

唯一Celery任务 `scheduled.stock_strategies`，复用analysis队列。A股19:00–23:50、美股22:00–23:50每10分钟检查；两地次晨07:00–08:50也检查。
一个任务内按市场本地窗口判断，不拆单策略子任务、不增加专用Worker。时区和调度以`definitions.py`为准。

盘后窗口控制的是当天结算日期，不阻止已结束交易日补算：CN当地19:00、US当地22:00之前，
手动运行或已有调度触发仅处理当地昨日及以前的闭合交易日；周末/节假日按交易日历回溯。
因此日线补齐后可立即重跑此前waiting的策略，无需等到今晚。成功日期仍幂等跳过，
计算时间保留真实当前时间，已过下一开盘的计划仍标记为历史计划。GET不触发补算。

- 每市场独立非阻塞PostgreSQL advisory lock；每策略/日期用状态行锁，状态、净值、成交/计划和success运行记录同事务提交。
- 相同日期幂等，不覆盖成功历史；每策略失败只回滚该项，记录原因后继续其他策略。共享输入失败影响依赖该输入的当日项。
- 单次每策略最多补5个交易日，全轮180秒预算，未完成留到下次；不在Worker里sleep等待上游。预算在日期间检查，DB读取/写入设置45秒statement timeout、5秒锁等待；冻结范围最多10000证券。预算并非对任意第三方代码的进程强杀。
- 停机后逐交易日补算，不跳过失败日。补算记录标记replayed，生成时已过下一开盘的计划标记next_is_historical，前端明确提示。
- TaskRecord通过现有`TaskOutcome`记录partial/failed；成功项不会因为其他策略失败而丢失。

## 存储与API

- `stock_strategy_launch`：启动锚点和冻结范围；

GET不启动模拟、不补行情、不回算收益。前端转换字段时保留证券代码字典键。

### NumPy 数值的持久化边界

日线指标来自Pandas/NumPy，基准收益从第二个结算日起、持仓账户的净值/回撤/成交金额等
可能为`np.float64`。NumPy 2的标量repr不能直接交给psycopg2适配（会产生
`schema "np" does not exist`）。每日引擎返回前递归将状态与快照中的NumPy标量转换为
Python原生类型，保持原数值，不注册进程级数据库adapter，不修改交易规则。

失败结算由原事务整体回滚，修复发布后复用原任务从最后成功日期继续，无需删除或覆盖历史。
`test_postgres_two_days_with_real_pandas_indicator_scalars`使用真实指标计算链分别检查空仓及持仓
连续两日保存；仅使用手写Python浮点输入的测试无法覆盖这一故障。

## 策略模拟前端第一阶段（2026-10-28）

汇总以独立账户卡片呈现累计收益、风险回撤、结算日收益和持仓比例；名称搜索、状态计数筛选与
收益/回撤排序保存在 URL query，返回列表保留筛选和会话内浏览位置。日期不一致及相对
`expected_date` 滞后单独提示；该日期是接口交易日参考，不代表当前已进入策略盘后结算窗口。
不同市场、版本、策略资金独立，不汇总为用户总资产或组合收益。

详情先展示状态、最后成功结算、实际计算时间与累计曲线，再以「持仓与计划 / 每日账本 /
策略规则」组织。图表近1月/近3月仅缩放原累计曲线，不重算区间收益。账本仍每次50条，日期与
成交筛选只作用于已加载记录；不为筛选下载全部重型明细。管理员检查通过现有Task接口跟踪，
任务终态自动刷新；任务结束与各策略结算成功是两个状态。

持仓展示口径：市值=股数×最后估值；净值占比=市值/账户净值；浮盈=股数×(估值−单股成本)，
比例以该持仓成本为分母；距有效ATR线=(估值−止损线)/估值。无效价格、数量或分母不算百分比，
缺值不填零；过期估值显示日期并提示。当前持仓浮盈不是策略完整收益。

计划保留冻结顺序，默认5个候选并可展开全部，不截断接口数据。候选总数不代表买入数，
满仓、暂停、待退出、无候选和历史补算状态可以同时显示。计划退出仅统计有原因的持仓，
不把`exits`字典中的空数组计为卖出；受阻退出与当日新计划原因去重合并。
不同策略评分定义不同，混合策略股票Trend60与ETF动量/波动率亦不使用统一评分尺度。

核对实现时需注意：`replayed`表示结算日早于本轮目标日，并非完整的按时在线执行认证；
`next_is_historical`表示生成时已错过计划执行开盘。前端保留真实计算时间与上述标记，
不将未标记补算的记录宣传为按时执行。`blocked`只记录实际检查到的开盘受阻事件，
不包括满仓后不再检查或因已持有等被跳过的全部候选。`attempts`为累计尝试数而非重试数。
本阶段不改变引擎、接口、数据库、排名、成交、估值或收益规则。

### 后续专业化能力顺序

1. 先固定输入快照、代码版本及数据可用时间，为复现和新口径对照提供基础。
2. 分离规则重放与按时在线模拟账户，记录漏执行与延迟；再建立独立订单生命周期与风险事件。
3. 引入费用、滑点、交易单位和流动性约束，并补公司行动、资金流水与账户对账。
4. 在可复现且可核对的账户上进行样本外验证、参数稳定性与成本压力测试。
5. 最后加入多策略资金分配、持仓重叠与组合风险分析。

任何收益或成交口径变更必须使用新版本或独立模拟账户；不覆盖旧收益，也不拼接不同口径曲线。

读取时若冻结计划执行日期不晚于接口参考交易日，另标为「此前冻结计划（等待结算）」，
不因原生成时`next_is_historical=false`就将过期计划突出为未来计划；这个展示判断不改写快照。

# 盘中确认 V2

确认昨日正式研究候选在今日的价格结构，不调用 LLM、不自动交易、不发送交易通知。
规则位于 `intraday_confirmation/config.py`，版本 `intraday_v2`，仍是未经回测验证的启发式观察。

## 候选与调度

CN / US 当地 09:20 首次冻结、09:25 重试；交易时段每 **5 分钟**评估一次。
使用交易所日历处理节假日、US DST / 半日市和 CN 午休；复用 `alerts` 队列与市场/交易日 PostgreSQL advisory lock。
严格读取前一个交易日、冻结前生成的正式结果：

| 来源 | 选择范围 |
| --- | --- |
| 共振精选 | `ConfluenceSnapshot.eligible=true` 的全部精选；当前上游门槛60分、最多10个。不是 `strong_confluence` 子集，不含观察行 |
| 趋势 | 20日正式综合 `rank` 1–30，不再按 CANDIDATE/TRENDING 二次筛选 |
| ETF轮动 | 正式综合 `rank` 1–5，不按候选状态或 entry score 二次筛选 |

允许 ACTIVE STOCK / ETF；正式 ETF 轮动成员即使 Instrument 粗标 STOCK 也作为 ETF 展示。
三组做并集、去重，保留全部 `candidate_sources`、各来源日期/排名/生成时间/理由，不再使用40只总截断。
不再读取 Quant。空池也冻结；冻结后不换池，错过盘前冻结不在盘中补建。不读取 Preview，不回退更早日期。

## 行情和完整性

业务全部经过 MarketDataService，仅请求候选与基准。CN 腾讯定向报价、原生1分钟新浪→腾讯单一降级；US yfinance 报价和批量原生1分钟线。
日线仅 DB 前复权，不补写。基准为 CN `510300.SH` / US `SPY.US`。
从当日开盘到当前读取完整窗口，保留常规交易时段的**已闭合1分钟线**，重复起点去重，非法 OHLC 排除。
`required_bar_starts` 要求开盘至允许的2分钟延迟边界之间的所有分钟：主源中间缺段也会降级。
完整窗口只能来自单一 Provider，不跨源拼接或补造分钟线。无完整来源时保持数据不足。
整个行情阶段预算210秒，本模块CN分钟请求共享该预算以容纳全池降级（其他调用仍默认最长90秒），沿用共享线程池、每源1QPS和部分失败隔离。

报价超过5分钟、分钟落后报价超过2分钟、开盘以来中间缺线时不推进状态；基准报价与证券报价差不得超过2分钟。
不使用抓取时间冒充行情时间。页面区分生成、报价、闭合线与首次确认时间。

| 指标 | V2口径 |
| --- | --- |
| 日内收益 | 当前报价 / 当日开盘 − 1；替代固定开盘15分钟硬门槛 |
| 全天等权均价 | 全部连续闭合1分钟线 `(H+L+C)/3` 的算术平均，不使用量权重 |
| 开盘区间 | 前5分钟的high/low；最近连续两根闭合1分钟线及当前报价均超过边界±0.1% |
| 相对大盘 | 证券开盘以来收益减基准开盘以来收益 |
| 近似VWAP | 全部闭合1分钟典型价按量加权；仅展示，不参与核心确认或追高风险 |
| 量比 | 累计分钟量 /（20日日均量 × 已过有效交易时间比例）；沿用线性近似，仅5分辅助 |
| 临时趋势 | 复用正式Trend纯函数，固定昨日横截面百分位；仅10分辅助，ETF缺少基线不阻断确认 |

固定开盘5/15/30分钟表现仍可作为历史兼容字段返回，但15/30分钟窗口不再参与状态判定。
若候选就是市场基准ETF自身，相对大盘项标为不适用、不计分，也不要求其跑赢自身；其余价格条件保持一致。

## 规则、状态和分数

原始 **CONFIRMED** 必须同时满足：突破开盘区间高点、当前价格高于全天等权均价、开盘至今收益非负、
无明显高开低走、相对大盘至少+0.3%（基准自身除外）。量能和Trend不是硬门槛。
原始 **FAILED**：连续两根1分钟线及当前价格跌破开盘区间低点，再叠加任一项：
距全天均价≤−0.5%、相对大盘≤−0.8%、高开≥2%且自开盘回落≥1.5%。Trend不单独决定失败。
其余 WAIT；证据不足不是看空。

状态变化需要连续两次不同且更晚闭合线评估，至少间隔240秒、最多间隔600秒；重复运行同一根线不累计，
缺数据或中断重置pending。正常每5分钟调度下，最早约09:45稳定确认（09:40与09:45两次有效评估）。
历史 `state` 为 WAIT / CONFIRMED / FAILED：CONFIRMED保留到稳定失败，FAILED当日锁定。
首次确认时间、价格和原始开盘价一经保存永不重设。

独立 `current_status`：
- PREOPEN：等待开盘。
- WAIT / PENDING：等待条件 / 等待两次稳定评估。
- ACTIVE：曾确认且当前仍满足条件。
- WEAKENING：曾确认，但当前不再满足条件。
- FAILED / RECOVERED：已结构失效 / 失效后当前条件修复（不撤销失效事件）。
- UNAVAILABLE：当前数据不足。当天交易时段GET也会按报价时间只读标记过期，不改变历史事件。
- LEGACY：旧版本未保存独立当前观察，不根据V2猜测。

评分：价格60 / 相对大盘25 / 趋势10 / 量能5。价格的突破、全天均价、日内收益三项各20分。
仅按可用权重归一化，减追高罚分0/5/10；展示有效权重。分数用于排序，不是概率，也不决定状态。
量比即使很高，原始贡献也封顶5分；量能或Trend缺失不妨碍价格确认。
高开≥5%、较昨收涨幅≥8%、距全天均价≥3.5%、开盘至今涨幅≥5%，任一触发HIGH；否则高开≥2%为MEDIUM。
必要行情缺失为UNKNOWN。允许确认有效同时追高风险高。

## 存储和历史兼容

每日冻结池和最新结果继续保存在 `intraday_confirmation_snapshot`；V2冻结时记录rule_version。
新增迁移 `0082_intraday_evaluation`：`intraday_confirmation_evaluation` 按market/trade_date/evaluated_at保存
每次评估的规则版本、条件命中、价格指标、辅助分数、当前/历史状态、原因和时间。不永久保存原始分钟线。
评估记录与每日快照同事务提交；任一写失败都回滚。原有revision CAS、行锁、首次价格不可变和收益持久化保留。
详情按需读取当天该证券轨迹；列表不下载整天轨迹。

旧V1历史只读展示，不重算、不补造轨迹；若部署时当日已冻结V1池，当日任务跳过新规则评估，下个交易日盘前开始V2。
冻结池不在部署过程中替换。历史Quant来源仍可读取和筛选。

### 首次确认收益率

- 仅在规则稳定状态第一次进入 CONFIRMED 时，冻结这一轮实际有效报价价格与原始开盘价；确认处理时间和报价时间分别保存。
- 3/5/10D 分别指**不含确认当日**的第 3/5/10 个交易所交易日收盘，按 CN/US 真实交易日历定位，处理假期、DST 与半日市；缺日不顺延。
- 收益率在 GET 时读取已持久化结果；尚未保存的期限可批量只读 `stock_daily` 计算，GET 不调用 Provider、不写任何数据。
- 首次确认价是原始盘中价格，而 DB 日线是前复权；用同日开盘价对齐：
  `当前前复权基准 = 冻结首次确认价 × 当前DB确认日open ÷ 冻结原始确认日open`，
  `收益率 = 目标日前复权close ÷ 当前前复权基准 − 1`。
  冻结价格保持不变。首次计算时确认日及窗口内日线必须来自相同 `data_source` 和完全一致的 `updated_at` 写入代次，
  才能证明共享复权尺度；单次查询并不能保证历史价格处在同一尺度。已有增量同步会忽略小幅复权变化，
  因此不能只依赖它的整段刷新判断。代次/来源不同或缺失时宁可留空，不推测因子。
- 既有确认任务每次先处理最多 10 个存在待到期收益的历史日，按最早检查时间轮转；即使当前不在交易时段也会检查。
  不新增 Beat 任务；正常工作日盘前/盘中调度自动补算，手动任务也可补算。第一次得到已成熟且同源同代次的完整窗口时，
  原子保存该期限的收益、完整 OHLCV 输入、来源、写入代次、目标日与计算时间。后续不覆盖已保存结果，
  避免历史滚出增量同步窗口或行情被清理后，原本有效的收益消失。历史查询不触发保存。
  未成熟/缺行情继续等待，超过 10D 不过期；始终缺失的旧记录通过轮转不会饿死较新记录。
  冻结时缺少不可补救的首次价格/开盘价/报价时间不会进入补算队列。若服务长期停止且历史已变为混合尺度，
  无法验证的未保存期限仍为空，必须等待一致的历史日线恢复，不进行猜测性回填。
- 确认日期/报价时间、正数价格或开盘对齐基准缺失、日历不可用、目标尚未收盘、
  确认日或期间任一交易日 OHLCV 缺失/无效（含停牌零量）时，对应期限为 null；表格留空，不显示 0%。
  较晚期限缺行情不影响已完整的较短期限。确认后转为 FAILED 仍保留首次确认收益。已保存的成熟收益不会因后续数据修订或更换来源自动重算。
- 这是事后价格收益观察，不代表真实成交、组合收益或含成本回测。

## API、页面和验证

- `GET /api/v1/intraday-confirmation?market=CN&trade_date=2026-10-30`：只读列表，来源筛选匹配全部来源集合。
- `GET /api/v1/intraday-confirmation/{code}`：详情；`/{code}/evaluations`：当日或指定日评估轨迹。
- `/dates`：历史日期；管理员 `POST /run`：只提交当日任务。
- 页面 `/research/intraday-confirmation`：概览、来源/历史状态/当前观察筛选、搜索、15行分页、统一证券详情。
  当前观察与历史确认分开展示，离散标签中文；历史日期不可运行当日任务。
- 后端测试：`uv run pytest tests/intraday_confirmation tests/test_cn_intraday_provider.py tests/test_celery_schedule.py -q`。
- 前端单测及 `web/e2e/intraday-confirmation.spec.ts` 覆盖中文、历史兼容、状态分离、详情轨迹和六档宽度深浅色。

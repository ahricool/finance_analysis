# 持仓复盘

`holdings_review/` 是按用户隔离的收盘前持仓研究，独立于已退役 Trade Engine 和美股盘后市场复盘。
不自动下单，不改变持仓/现金，不推荐新股票；BUY 只表示对已登记持仓加仓。

## 调度与完成边界

- 原 `analysis_a_share_pre_close_review` 改为北京时间 14:10。
- 新 `analysis_us_pre_close_review` 在纽约 15:10；NYSE 提前 13:00 收盘时为 12:10。
- 两市均按实际交易日与收盘前 50 分钟检查，允许 15 分钟的排队/手动触发窗口。
- 每个市场 tick 向 analysis 队列投递有该市场投资组合账户的用户任务，用户持仓不合并。
  空仓用户仍生成市场观察和空仓说明，不凭空新建仓建议。
- uid+market 的 PostgreSQL session advisory lock 覆盖采集、LLM 和落库，获取锁后不保留业务事务。
  唯一键 `(uid, market, trade_date)` 保证完成结果不被重跑覆盖，每用户每市场每天只生成一份消息。
- LLM/外部采集在数据库事务外。结果与站内通知同事务保存，随后推送；推送失败不回滚复盘。

## 冻结输入与预算

读取实际 PortfolioResolver 的数量、成本、批次、账户现金，行情只经 MarketDataService。
本任务不扫描/发送几千只股票快照，不重算上游研究。

| 输入 | 保留内容 |
| --- | --- |
| 主要指数 | CN 上证/创业板/沪深300，US 标普500/纳指100/道指；各20根历史日K、当前报价与今日OHLCV。指数点位不以ETF冒充 |
| 每笔持仓 | 账户/position ID、证券、数量、成本、现价、盈亏与权重、今日OHLCV、当日买入剩余量 |
| 持仓历史 | 最近20根已完成的前复权日K；不混入今日未收盘日线 |
| 持仓分钟 | 当天原生闭合1min聚合5min，最近12根完整窗口；不补零、不预测全天量 |
| ETF预演 | 当日有效批次前5名的代码、名称、排名、综合/动量分和候选资格 |
| Trend预演 | 只读取持仓标的的20日预演，取state、alpha、生命周期与脆弱度 |
| 行业预演 | CN前5个行业的强度、排名、广度与加速度；US明确标为不覆盖 |

预演只接受当日、观察时间不晚于任务时点、数据时间不超过20分钟的批次；缺失/过期不回退旧正式结果。
股票报价需属于当日且不超过180秒；主动建议还要求至少10根历史日K且最新日为上一交易日，
至少6根完整5min线且尾部新鲜。缺失时主动建议被程序降为WATCH。
K线使用一次声明的 `[time, open, high, low, close, volume]` 紧凑数组；不传成员全集、诊断明细或完整评分拆解。
输入超过160,000字符时明确降级，不静默丢弃部分持仓。

## LLM 与结构化建议

每用户每市场一次业务级 LLMClient 请求，`call_type=holdings_review`，传 uid，允许 web_search。
共享客户端仍可能重试或切换渠道。检索范围限已有持仓、主要指数及相关板块的公告、财报与风险。

输出经 Pydantic 校验：市场状态/结论/置信度、最多6项板块观点、6项风险、逐笔建议及观察事项。
动作仅 HOLD/BUY/REDUCE/SELL/WATCH；比例相对该笔现有持仓，SELL为100%，HOLD/WATCH为0。
BUY必须给条件，合计建议新增市值不能超过登记现金；估值不完整不输出BUY。
未知symbol/position、重复持仓、非有限数字或违规比例会拒绝；遗漏持仓补为WATCH。
CN当日买入部分按T+1扣减可卖比例；全为当日买入时卖出建议降为WATCH。最终可卖数量仍由用户核对券商。

未配置/失败/结构化校验不通过时，保存低置信度WATCH降级复盘并明确标注，不伪装模型成功。
联网执行证据来自transport，模型自己写的来源不能证明检索成功。仅展示经过协议检查的http(s)来源。

## 存储与 API

迁移 `0088_holdings_review` 创建私有 `holdings_review` 表，保存冻结输入、结构化结论、Markdown、
transport检索证据、模型/状态/时间及通知关联。旧全局A股报告无法推断用户归属，不导入个人历史。

- `GET /api/v1/holdings-review?market=CN|US&trade_date=YYYY-MM-DD`：只读本人快照。
  无日期时优先今日，没有今日记录才取上一交易日；明确选历史日期时不回退到其他日期。
- `GET /api/v1/holdings-review/dates`：本人该市场历史日期（最多3660个）。
- `POST /api/v1/holdings-review/run`：仅当前交易日复盘窗口，异步投递本人任务；不提供历史重算。
- 所有读取要求登录，设置 `private, no-store`；客户端不能指定其他uid。

每天每市场一份合并Markdown写入本人消息中心并外推，同一份结构化结果供页面展示和Markdown下载。
用户收件地址来自本人通知设置；无个人地址的普通用户仅站内保存，不能把私人持仓发到全局收件地址。
默认管理员无个人地址时沿用部署通知配置；Telegram/ntfy沿用现有路由、降噪和通道长度限制。

## 页面与验证

`/market/holdings-review` 位于“市场 → 投资组合”下方，复用顶栏市场开关。
提供市场结论、指数、组合快照、板块强弱、风险、持仓操作建议、条件/失效情景、证据与数据时点。
日期选择只读历史，切市场清日期并使旧响应失效；支持空态、失败、降级和处理中自动刷新。

离线回归：`tests/holdings_review/`；真实PostgreSQL用 `HOLDINGS_REVIEW_TEST_DATABASE_URL` 指向隔离测试库。
前端：`HoldingsReviewPage.test.ts`、`e2e/holdings-review.spec.ts`（6种宽度与深浅色）。

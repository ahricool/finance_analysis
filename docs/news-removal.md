# 新闻采集与分析退役

美股盘前新闻情报已完整退役，不再调用Longbridge Content API抓取新闻，也不再执行新闻重要性和影响判断。

删除范围包括Beat定义、Celery任务注册、新闻Prompt与服务、Longbridge新闻适配器、
新闻输入类型、数据库存取方法、ORM及时间线新闻页签/卡片/详情。
该次退役移除了美股收盘复盘和期权解释的新闻依赖。美股收盘复盘随后也已退役，见 [退役说明](us-postmarket-removal.md)；期权解释保留财经日历。

## 现有数据清理

迁移 `0086_retire_news` 接在 `0085_retire_market_review` 后：

- 按子表到父表删除 `news_analysis`、`news_intel_usage`、`news_intel`，包含全部历史数据。
- 删除 `scheduled_us_premarket_news` 或 `scheduler_job_id=analysis_us_premarket_news` 的全部任务记录，包含未完成任务。
- 删除任务结果关联的站内消息、盘前新闻专属报告和明确标记该任务类型的错误通知。
- 删除两种新闻LLM调用的用量与当前审计目录内对应JSONL行：
  `us_premarket_news_importance`、`us_premarket_news_impact`。
- 删除日志根目录内已关联的任务日志与该任务专属日志；目录外路径不删除，混合审计文件保留其他任务行。
  审计目录沿用 `LLM_LOG_DIR`，与应用配置一致支持 `~/...` 路径。

清理支持重复执行和新闻表部分/全部不存在的数据库。删除不可逆，downgrade明确拒绝。
离线SQL只清理数据库，专属日志清理需要正常在线执行Alembic迁移。

## 保留范围

宏观和财报事件 `finance_events`、财报研究全部状态/版本/验证记录、财经日历同步及事件重要性评分继续保留。
时间线和Dashboard只展示宏观与财报。财报详情、高置信度筛选、手动刷新、事件来源及游标分页保持可用。
旧新闻/分析类型查询与旧新闻游标返回422。

Longbridge行情、Streamer、财经日历、共享LLM、信号中心的既有研究能力不随新闻任务删除；交易引擎另由 `0087_retire_trade_engine` 退役。
不删除证券主数据、自选股、持仓、Universe、日线、其他任务的通知、用量或日志。

## 发布与验证

按标准部署流程暂停Beat并等待旧Worker退出，然后部署新代码并执行迁移。
迁移不清空共享Redis队列；极端情况下残留旧任务消息会因处理器已删除而被拒绝。
不通过重新运行旧任务清理数据。

离线测试覆盖任务/模型退役、SQLite和PostgreSQL清理、重复迁移、部分表存在、通知归属、
日志目录边界、混合审计文件保留、宏观与财报数据保留，以及时间线和期权/复盘回归。
生产数据会在实际部署执行迁移时清理，代码修改本身不代表生产迁移已经执行。

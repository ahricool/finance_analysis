# 最新研究 Preview 存储

迁移 `0078_research_preview` 将 Trend、ETF Rotation、Industry Strength 和 Options Intelligence
的研究预演迁入 PostgreSQL，使用 `research_preview` 和 `research_preview_item` 两张独立表。
不复用正式策略快照、股票日线或期权正式日度表。行情 Provider 的短期请求缓存、Streamer 分钟线
以及正式结果的读缓存不属于研究 preview，仍按各自原有规则使用 Redis。

## 范围与替换

批次主键为 `(namespace, market, variant)`：Trend 的 variant 为 20/40/60，其他模块为 0。
每个范围只有一条批次，明细主键额外包含 kind 和 item_key；没有时间版本历史。
新结果在同一事务中锁定批次、DELETE 对应旧明细、插入本轮明细、更新摘要。
使用范围 DELETE，避免 TRUNCATE 清掉其他市场、周期或模块。
数据库写入失败整体回滚；Trend/ETF 使用冻结的本轮启动时间（生成时间仍单独保留），晚到的旧 observed_at/旧交易日不会覆盖新结果。
读取通过批次共享行锁和限定范围的查询获取同一版本，状态接口不查询明细，单股接口只查该股。

Trend、ETF、行业沿用 24 小时有效期，期权到纽约当地午夜失效，API 不返回过期数据。
过期的最新行可以在数据库中等待下次替换，但不会累积其他历史版本；DELETE 后的物理页回收由
PostgreSQL autovacuum 管理，不意味着数据库文件每次缩小。

行业任务开始新一轮时清空上轮结果，失败只留下本轮失败状态。
期权全范围扫描开始时清空旧范围，再按股提交本轮检查点，避免 Worker 超时丢掉已完成结果。
单股刷新只替换该股；失败删除该股上次详情并记录失败原因。其他标的仍保留各自最新观察。
新交易日期不合并前日数据。

## 去重与取舍

- 不再同时存完整 preview 文档、全量详情 HTTP 响应及排名副本。完整接口按需组装。
- Trend、ETF 的所有股票共有的精确相同字段/参数子树只保存一次。缺失与 null、false、0
  不混淆，不做小数取整。评分参数保留计算时值，不从后来变化的代码配置重新推导。
- 已有 Instrument 的证券名称不存明细，批量关联证券主数据；没有匹配主数据的名称保留原值。
  名称属于当前展示标签，指标/排名仍属于该轮观察。
- Trend 把列表所需标量与完整诊断拆开，排名所需评分项从诊断移入轻量字段，详情读取时无损还原；广度只读状态标量。
  详情中的每个计算值只在一份 canonical 数据中保存。
- 行业排名和各行业成分拆行存储，列表不加载所有成分；成分名称也复用 Instrument。
  行业归属、当轮成分集合、Trend Rank 日期及排名值保留，不能用后来周同步的成员或最新正式排名替换。
- 期权摘要与合约/事件详情拆分，top_event 从事件数组提取只保存一次，详情读取时还原原顺序。
  新出现的盘中合约可能没有正式 OptionContract；合约来源、报价/OI 时间和原始观察继续保存，
  不依赖日后更新的正式表，不将盘中观察写进正式历史。
- 不从 stock_daily 或正式 Trend/ETF 快照重算盘中价格、技术指标、评分或临时日 K。
  这些值即使字段名一致，观察时间与计算输入也不同，不能作为冗余删除。

## 部署与验证

应用部署正常执行 Alembic。新版本直接读取新表，首次没有结果时显示既有空态，下一次正常
Preview 任务写入；不读回旧 Redis preview。旧研究 preview key 停止续期后按既有 TTL 自然过期，
通常不超过 24 小时，期权到纽约午夜。无需清空 Redis，避免影响 Celery 队列和行情缓存。

离线测试：`uv run pytest tests/research_preview -q`。
并发与真实 JSONB/迁移测试需显式设置 `PREVIEW_TEST_POSTGRES_URL` 指向隔离的测试数据库；
测试创建唯一 schema，结束后删除，禁止指向业务数据库。
